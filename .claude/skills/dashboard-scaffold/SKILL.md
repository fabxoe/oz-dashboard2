# dashboard-scaffold

규칙은 하나: **폴더 하나 = 대시보드 하나, 파일 구성은 항상 같게.** 작게 시작하고 필요할 때만 늘린다.

## 구조

```
<프로젝트>/
├─ index.html              # 대시보드 목록 (링크 모음)
├─ README.md               # 규칙 한 페이지
├─ data/                   # 데이터 CSV (탭/테이블당 1파일)
├─ shared/                 # style.css, lib.js (두 개로 시작)
└─ dashboards/
   ├─ _template/           # 복사해서 시작하는 원본
   │  ├─ index.html
   │  ├─ main.js
   │  └─ README.md
   └─ <이름>/              # _template과 같은 3개 파일
```

## 절차

1. **프로젝트 초기화** (루트에 `dashboards/_template`이 없을 때만)
   - 이 스킬의 `assets/` 안 파일을 같은 경로로 프로젝트 루트에 복사한다. 이미 있는 파일은 덮어쓰지 않는다.
   - `data/` 폴더를 만든다.
2. **새 대시보드 추가**
   - 이름은 kebab-case (예: `claims-overview`).
   - `dashboards/_template/`을 `dashboards/<이름>/`으로 복사한다.
   - 루트 `index.html` 목록에 링크 한 줄을 추가한다.
3. **인터뷰** (한 번에 2~3개씩 묻고, 답을 새 폴더의 `README.md`에 채운다)
   - 목적: 누가, 어떤 결정을 하려고 보는가
   - 핵심 지표 3~5개와 정의(분자/분모, 기간)
   - 필터/나누어 볼 기준 (기간, 지역, 상병 등)
   - 쓸 데이터(테이블, 컬럼)와 크기. 큰 파일은 미리 집계한 CSV를 `data/`에 따로 둘지 결정
   - 차트 종류, 화면 구성, 우선순위
4. **구현**
   - README의 지표 순서대로 `main.js`를 채운다. 공통으로 쓰는 코드가 두 대시보드에서 반복될 때만 `shared/lib.js`로 옮긴다.
   - 브라우저로 열어 콘솔 에러 없이 렌더링되는지 확인한다. `file://`에서 CSV 로드가 막히면 `python3 -m http.server`로 연다.

## 하지 않는 것

- 스크립트, 빌드 도구, 프레임워크를 처음부터 넣지 않는다.
- 필요가 생기기 전에 폴더(`scripts/`, `components/` 등)를 추가하지 않는다. 늘릴 때는 루트 `README.md`에 규칙을 한 줄 적는다.

## 화면 원칙 (템플릿에 반영됨)

- **한 가지 질문**: 인터뷰에서 화면의 질문을 한 줄로 정한다. 가장 큰 숫자(`.kpi.lead`, 36px)가 그 질문에 답한다. 나머지 숫자는 22px.
- **핵심 발견 한 줄**: 제목 아래 `.finding`에 데이터로 계산한 문장을 둔다. 숫자는 `<em>`으로 강조한다.
- **제품 표식**: 맨 위 `.brand`에 이름, 담당/범위, 데이터 기준일을 둔다.
- 숫자 띠는 타일 여러 장이 아니라 선으로 나뉜 한 칸짜리 컨테이너로 만든다.
